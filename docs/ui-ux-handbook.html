● Design system reference · v1.0

The NoPS interface, documented end to end.

NoPS turns uploaded business data into dashboards, forecasts, alerts, and board-ready reports. Its interface has to make deterministic, auditable numbers feel calm and trustworthy — dense analytics without visual noise. This handbook captures the tokens, components, patterns, and experience decisions that make that possible, and closes with a working UX audit of the current build.

React 18 + TypeScript Tailwind · dark-first Framer Motion Inter / JetBrains Mono 15 routes
01

Design principles

Five commitments the product's positioning imposes on every screen. When a design decision is unclear, these break the tie.

Trust is the primary job

Every number is deterministic and reproducible. The UI must never make a computed figure look like a guess — clear provenance, no decorative ambiguity, and a visible separation of observed data from possible cause from recommendation.

Calm density

Analytics screens are information-dense by nature. Restraint — generous spacing, one accent hue, muted neutrals — keeps them scannable. Color is spent on meaning, not decoration.

Summary before detail

Screens are operated, not read. KPIs and headline state surface first; tables and raw rows follow. What needs attention reads at a glance through a pill, chip, or delta color.

Motion with a reason

Physics-based, fast, and purposeful — entrance choreography and micro-interactions that orient the user, never ambient flair for its own sake. Everything collapses gracefully under prefers-reduced-motion.

Chart series order is fixed: blue → violet → teal → emerald → amber → rose. Revenue is always chart-blue; profit is always emerald. Consistent hue-to-metric mapping means a returning user reads a chart before they read its legend.

Neutrals are chosen, not default

Surfaces carry a faint blue bias rather than pure grey — surface.tertiary #f1f3f8 in light, and a near-black #060a13 ground in dark washed with three fixed aurora radial-gradients (blue, violet, cyan). Borders step through #e2e6ef → #eef1f7 → #cdd3e0 so hierarchy survives without heavy lines.

06

Motion

A single source of truth (lib/motion.tsx) so every timing matches. Entrance/exit is Framer's job; looping ambient effects stay on the GPU as CSS keyframes.

Tokens

Named patterns

  • fadeUp / fadeIn / scaleIn — element entrances
  • Stagger — grid & list choreography (0.06s children)
  • Reveal — scroll-triggered, plays once
  • AnimatedNumber — KPIs count up to value
  • Ambient CSS: aurora, float, sheen, shimmer

Reduced motion is a first-class path, not a filter. Reveal/Stagger render in their final state immediately; the skeleton shimmer stops; all durations collapse to ~0. Content is never gated behind a scroll trigger that never fires.

07

Buttons

Five variants × three sizes, with a built-in loading state. Hover lifts -1px, tap scales to 0.97 — transform is Framer's; only paint properties transition in CSS.

Primary = the one obvious action per view. Danger is reserved for destructive, irreversible operations. Ghost/outline carry secondary and tertiary actions so a screen never shows two competing filled buttons.

08

Forms

Consistent 40px control height, 8px radius, and the shared 3px brand focus ring across Input, Select, Textarea, Checkbox, and Switch.

Focus is the single most important state in a form — it always draws the 0 0 0 3px rgba(51,102,245,.25) ring plus a brand border, never a bare browser outline.

14

Key experience flows

First-run → first insight

  1. Sign up → guided Onboarding
  2. Drag-drop a CSV/XLSX (or use sample retail data)
  3. Automatic parse, profile & quality check
  4. Schema detected → dashboard renders
  5. KPIs count up; trends reveal on scroll

The sample dataset guarantees a populated dashboard even before the user uploads anything — no empty first impression.

Ask a question

  1. Type plain English in Chat with Data
  2. Question → structured intent (AI or rules)
  3. Deterministic engine computes the answer
  4. Result renders as a KPI, table, or chart

The UI reinforces trust: it shows the interpreted intent, and every figure traces to reproducible code, never a model.

15

Accessibility

Built in

  • Visible 3px focus ring on every interactive element via :focus-visible
  • prefers-reduced-motion honored globally and per-component
  • Status encoded in shape + text, not color alone
  • Semantic color-scheme declaration for native form controls
  • Dark and light themes both ship, persisted to localStorage

Verify per screen

  • Contrast of muted text on dark ground (slate-400 on #060a13) at small sizes
  • Chart series distinguishable without color (patterns / labels)
  • Keyboard reach into Dropdown, Modal focus-trap, and the mobile slide-over
  • Screen-reader labels on icon-only buttons and KPI deltas
16

UX audit

A working assessment of the current build against the principles above. Each finding is tagged keep a proven strength, watch a risk to verify, or fix a concrete gap.

Trust is designed, not claimedkeep

Separating observed data / possible cause / recommendation in insights, and showing interpreted intent before answers, turns "deterministic and auditable" from a tagline into a felt UI property. This is the product's strongest differentiator — protect it in every new surface.

One coherent visual systemkeep

Centralized tokens (tailwind config + index.css) and a single motion source mean the whole app moves and looks as one. The barrel-split ui.*.tsx primitives keep the component surface small and consistent.

Shareable URL statekeep

Analytics filters living in the URL is a high-value, low-cost collaboration feature that most dashboards miss. Extend the same pattern to Forecasts and Chart Library.

Dark-mode contrast on muted textwatch

slate-400 / slate-500 body copy over the #060a13 aurora ground can dip below WCAG AA at body-sm and label sizes, especially where an aurora gradient lightens the background locally. Audit with a contrast checker over the actual gradient, not a flat swatch.

Chart accessibility beyond colorwatch

The six-hue series palette is distinct for typical vision but blue/violet and teal/emerald pairs can collapse under deuteranopia. Add direct labels, dash patterns, or a texture fallback for multi-series charts and donuts.

Motion budget on data-heavy pageswatch

Stagger entrances + AnimatedNumber count-ups + ambient aurora are delightful once, but on a dashboard the user reloads twenty times a day they can start to feel slow. Consider a "first visit only" or session-scoped entrance so returning views are instant.

Empty and error states need a full passfix

EmptyState and ErrorState exist, but confirm every async surface (Forecasts, Alerts, Reports, Chat) actually renders them — with a specific recovery action, not a generic "try again". Errors should say what went wrong and what to do.

Icon-only controls need labelsfix

Sidebar toggles, pagination arrows, and row-action dropdowns rendered as bare icons need aria-labels and a tooltip so both screen-reader and mouse users know what they do.

Table density controlsfix

Analytics data tables will grow long. Sticky headers, a comfortable/compact density toggle, and per-column sort indicators are missing pieces that materially affect scanning large result sets.
